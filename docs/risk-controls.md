# 交易硬约束

约束由 Java 后端执行，模型无法修改配置、解除熔断或直接向交易所下单。模拟盘与实盘的风险配置、状态和账户绑定分别保存。旧的基础风险设置保持兼容。

## 默认参数

以下为初始软件配置，需要通过模拟盘验证，并非收益或最大实际亏损保证。

| 参数 | 默认值 |
|---|---|
| 单笔预估亏损 / 权益 | 0.5% |
| 保证金占用 / 权益 | 60% |
| 同方向敞口 | 200 USDT |
| 相关组总敞口 | 250 USDT |
| 峰值回撤熔断 | 5% |
| 连续亏损熔断 | 3 笔完整平仓 |
| 每小时开仓 | 3 次（包含被拒绝及结果不明的提交） |
| 同币种开仓间隔 | 900 秒 |
| 完整平仓后的冷却 | 3600 秒，盈利退出同样适用，覆盖移动止损盈利退出 |
| 未成交订单撤单阈值 | 60 秒 |
| 单边手续费预算 | 10 基点，即 0.1% |
| 单边滑点预算及最大预计滑点 | 20 基点，即 0.2% |
| 买卖价差上限 | 10 基点，即 0.1% |

日内损失、白名单、总敞口、持仓数、杠杆沿用基础设置。默认日损为 3%，杠杆为 1 倍，允许配置最高 3 倍。所有支持的加密合约保守地归为一个相关组，不将多空相抵，不使用未经验证的实时相关系数。

## 执行方式

1. 检查交易所 UID、合约账户模式和单向持仓；同一环境一个交易所 UID 只允许绑定一个用户，首次绑定后不能切换。只管理有本地成交记录且交易所仓位身份、创建时间、最近成交标识、方向、数量匹配的逐仓仓位。
2. 开仓数量取模型提出的敞口、基础单笔额度和止损风险预算所允许数量中的限制值。模型超出基础单笔额度直接拒绝。止损每单位风险包含价格距离及双边手续费、滑点预算，向下取整到合约数量精度，低于最小数量则拒绝。
3. 总敞口按全账户仓位计算，同方向和相关组同样计算本次执行后的合计值。保证金占用使用权益减可用余额的非负值，加上本次所需保证金。存在普通挂单、本地未确认订单，或非当前策略保护单的条件/止盈止损/触发/移动止损算法挂单时禁止新开仓，不预先假设它们会撤销。
4. 每次监控及下单前更新日内权益基准与峰值。熔断持久化，不因重启、权益回升、跨日或模型建议自动解除。连续亏损以交易所完整平仓历史中的 `realizedPnl` 为依据，包含交易所返回的费用和资金费；历史缺失或身份无法对应时禁止新增风险。亏损后下一笔名义金额不得大于此前亏损仓位，盈利完整平仓后解除这一额外额度限制。
5. 盘口使用最多 400 档，按合约张数计算成交均价，验证时间（最多 5 秒）、价差、深度及相对最新参考价的预计滑点。适用于开仓及普通减仓/平仓。发送前再次检查账户快照时效和用户暂停状态。
6. 先保存订单意图，再发送带唯一 `clOrdId` 的订单。提交超时不重发。查单按累计成交量差值记账，重复查询不重复累计。未成交超时只请求撤单，仍以之后的查单结果确认最终成交和撤销状态。
7. 完整保护单必须属于当前策略开仓，方向正确、保护数量精确匹配。止损相对已记录值只能收紧；发现外部放宽、保护缺失或部分成交数量不匹配，停止自动交易并继续监控。人工减仓/平仓仍须验证归属、行情和订单状态。
8. 模型通信、解析、资讯证据或建议风控校验失败时返回 HOLD 并记录 `AI_SKIPPED`，不提交订单。服务重启默认暂停，启用前完成查单、持仓和保护核对。

## 配置与人工复核

手机「运行设置 → 硬性风险约束」显示并修改配置，修改前必须暂停。状态接口包含 `riskPolicy` 和 `riskStatus`。API：

- `PUT /api/risk-policy`：提交完整 RiskPolicy 配置，服务端校验边界并记录修改日志。
- `POST /api/risk/reset`，请求体 `{"confirm":true}`：人工复核解除熔断。要求暂停、空仓、无挂单、无未确认订单、当日亏损未超限。重置峰值基准和连续亏损次数，保留冷却及亏损后额度限制，不自动开启交易。

两个接口沿用登录鉴权和 `X-Trading-Environment`。模型没有这些接口的调用权限。

## 升级与验证边界

Flyway V4 创建风险配置、风险状态及交易所 UID 绑定表，不修改原有订单。升级前已经存在的仓位不会自动认领，避免把人工仓位当作策略仓位；应先在交易所核对处理，再开始新策略周期。平仓历史无法匹配时同样保持阻断。

手续费是可配置预算，须覆盖账户实际费率；资金费率未用于预测持仓期间的未来成本，但已实现损益统计采用交易所返回值。市价单及止损市价单在剧烈行情中仍可能超过预计滑点和风险预算。盘口检查不能锁定实际成交价格。外部手工交易无法与程序获得同一执行锁，应使用独立账户；检测到外部变更时保守停止。

保护异常不会擅自补挂或强制平仓；后台继续查单，界面显示错误，由用户核对处理。订单和持仓 REST 快照不是原子读取，短暂不一致也可能触发暂停。平仓历史查询为该合约最近 100 条；超出窗口无法核实时不继续开仓。权益充值、提现可能影响日损及回撤判断。

交易所字段依据：[OKX API 官方文档](https://www.okx.com/docs-v5/en/)，包括账户配置、盘口、查单、撤单和持仓历史。自动化测试使用模拟交易所响应；真实成交和保护单生命周期仍需模拟盘联调。
