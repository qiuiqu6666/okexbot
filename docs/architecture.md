# OKX AI 仓位管理系统

## 已确定

- 后端 Java，数据库 MySQL，客户端 Flutter。
- 接入 OKX，使用 AI 辅助自动操作仓位。
- 当前目录为空，从独立项目开始，不复用参考仓库的交易代码。

## 第一版确定范围

- 单用户、单 OKX 账户、USDT 本位永续合约。
- 默认模拟盘，服务启动时自动交易关闭。
- Flutter Android 和 iOS；AI 使用可配置的 OpenAI 兼容接口。
- AI 可提出 HOLD、OPEN_LONG、OPEN_SHORT、REDUCE、CLOSE、UPDATE_STOPS。
- 支持 AI 自动开仓、减仓、平仓及收紧止盈止损。

## 架构

Flutter → 带身份验证的 REST API → 应用服务 → MySQL

后台调度 → 读取 OKX 账户、持仓、行情 → AI 决策 → 独立风控 → 订单执行 → 订单与持仓对账

Flutter 负责显示与控制，持续运行的交易循环在 Java 服务端执行。关闭手机应用不会终止服务器上的交易任务。

## 后端模块

1. 身份与配置：访问控制、交易环境、币种白名单、模型、风险参数。
2. OKX 适配：请求签名、账户模式检查、合约元数据、余额、持仓、订单、止盈止损。
3. 行情上下文：K 线、价格、资金费率；校验时间戳与数据完整性。
4. AI 决策：只接受结构化动作，拒绝未知字段/动作、非有限数值、过期决策；不向模型提供密钥。
5. 风控：单笔风险、总敞口、持仓数量、杠杆、日内回撤、冷却时间；减仓不得意外反向开仓。
6. 执行与恢复：先持久化订单意图，唯一客户端订单号；超时进入待确认状态，查单对账后才决定后续操作。
7. 审计：记录模型输入摘要、决策理由、风险拒绝原因、订单状态变化和用户操作。

## 第一版 MySQL 数据结构

- bot_config：机器人参数；启停状态仅保存在进程内，重启默认暂停。
- order_intent：唯一客户端订单号、动作、数量、请求摘要、执行状态。
- equity_baseline：UTC 当日首次观察的权益基准。
- execution_lease：单账户执行锁。
- audit_event：人工操作、系统异常、模型决策和当时的账户/价格快照。

第一版将决策与账户快照放入审计事件 JSON；独立的决策表、逐笔成交事件、连续权益曲线和持仓时序表留待后续扩展。

金融数量使用 DECIMAL；时间统一 UTC。凭据不进入普通配置 JSON 或日志；第一版本优先从服务端环境变量注入。

## 交易约束

- 永续合约 sz 按合约张数处理，使用 ctVal、ctValCcy、lotSz、minSz 换算并向下取整。
- 明确校验持仓模式和 tdMode，不能把单向与双向持仓参数混用。
- 交易所响应成功只代表请求被接受，不代表成交；以订单状态、成交与持仓对账为准。
- 创建保护单失败必须标记异常并禁止继续增加风险。
- 暂停交易意味着停止新增自动指令，不隐含撤销保护单或立即平仓；紧急平仓是独立操作。
- 第一版按单实例部署；数据库租约用于阻止意外重复启动的服务并发执行。启停状态为进程内状态，服务重启默认暂停。

## 验证

- 单元测试：签名、张数换算、风控、减仓方向、模型输出校验。
- 集成测试：持久化、重复请求、超时查单、重启恢复、部分成交、保护单失败。
- Flutter：静态分析和关键操作组件测试。
- OKX 模拟盘端到端验收需要用户在本地配置模拟盘凭据，不能用模拟响应冒充真实联调成功。
